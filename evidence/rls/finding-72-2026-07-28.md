# Finding 72 (P0) — anonymous writes to bookings / leasing_requests

Applied to Production 2026-07-28 via the Supabase SQL editor.
Migration: `scripts/2026-07-28-revoke-public-insert.sql` (includes the rollback).

## What was actually there

`pg_policies`, before:

| table | policy | roles | cmd | USING | WITH CHECK |
|---|---|---|---|---|---|
| bookings | Public can create bookings | {public} | INSERT | (none) | **true** |
| bookings | Service role manages bookings | {public} | ALL | `auth.role() = 'service_role'` | (none) |
| bookings | availability_check_only | {public} | SELECT | `auth.role() = 'service_role'` | (none) |
| leasing_requests | Public can submit leasing requests | {public} | INSERT | (none) | **true** |
| leasing_requests | Service role manages leasing requests | {public} | ALL | `auth.role() = 'service_role'` | (none) |

The `Service role manages …` policies are granted to `{public}` but restricted by
`auth.role() = 'service_role'`, so they were never the problem. The two
`Public can …` policies with `WITH CHECK true` were.

Grants, before — **broader than the audit recorded.** The tracker says anon holds
INSERT; in fact `anon` and `authenticated` each held:

```
DELETE, INSERT, REFERENCES, SELECT, TRIGGER, TRUNCATE, UPDATE
```

on **both** tables. Only INSERT was reachable, because no permissive policy
existed for the other commands — but the grants sat one careless policy away
from anonymous `DELETE` or `TRUNCATE` on the bookings table.

## Why it was safe to revoke everything

All 13 files referencing these tables live under `src/app/api/**` or
`src/lib/db/**` and use `createAdminClient()` (service role, bypasses RLS).
No client component touches either table. The two files that also import the
anon client — `my-bookings/route.ts` and `my-bookings/cancel/route.ts` — use it
only for `auth.getUser()`; every `.from('bookings')` in them goes through the
admin client. Checked before applying.

## After

| check | want | got |
|---|---|---|
| permissive INSERT policies for public/anon/authenticated | 0 | **0** |
| anon/authenticated grants of any kind | 0 | **0** |
| service_role INSERT intact | 2 | **2** |
| RLS enabled on both tables | 2 | **2** |
| bookings rows | unchanged | **47** |
| leasing_requests rows | unchanged | **4** |

No data was read, written or deleted. The change touches permissions only.
